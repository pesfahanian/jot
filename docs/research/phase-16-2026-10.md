# Phase 16 research: auto-fix spelling and translating a selection (2026-10-20)

Two questions before building Phase 16 (docs/todo.md). Both measured or tested here, not only read about.

## 1. Auto-fix spelling: which dictionary, and which fixes are safe

A web page can't read the browser's own spellchecker, so Jot needs its own.

**Library: nspell** (MIT, wooorm), a Hunspell-compatible checker in plain JavaScript, about 110 KB unpacked. It has no tokeniser: Jot splits words itself, which it does anyway (code, links, Farsi).

**Dictionaries: dictionary-en (en_US) and dictionary-en-gb (en_GB, -ise)**, both "(MIT AND BSD)", built from SCOWL / wordlist.sourceforge.net. Each is about 555 KB raw and 192 KB gzipped, so about 384 KB for the two. They load only when auto-fix is switched on.

Measured in Node on this machine:
- Loading a dictionary takes about 52 ms.
- `correct()` is instant. `suggest()` takes 1–7 ms for a typical typo. One capitalised unknown word ("Kubernetes") took 61 ms, but capitalised words are skipped anyway.

**nspell's suggestions can't be applied blindly.** Its first suggestion is often wrong for the most common typos:
- "teh" → "ten"
- "thier" → "thief"
- "hte" → "hoe"
- "ok" is unknown
- en_US alone would "fix" "colour" to "color"

**The rule that tested well** fixes a word only when all of these hold:
- it's lowercase, 3+ letters, and unknown to both dictionaries
- *and either*
  1. swapping one pair of neighbouring letters gives **exactly one** real word ("teh" → "the", "thier" → "their", "adn" → "and", "freind" → "friend"),
  2. *or* there's no such swap, and the two dictionaries together offer **exactly one** suggestion ("definately" → "definitely", "occured" → "occurred").

On a list of 52 common typos and real words, it fixed 40, all correctly but one: "alot" → "alto". That one needs a short never-fix list. It left alone words with more than one plausible fix ("wierd": weird or wired?), and every real word ("form", "fro", "colour", "color", "jot").

**Caveat:** it never catches a typo that is itself a real word ("form" for "from"). That's the price of never changing a word that's already correct.

**Farsi:** an Apache-2.0 Hunspell dictionary exists (Lilak, github.com/b00f/lilak), but nobody has tested nspell against Persian affix rules. The round 4 design already says auto-fix stays off on right-to-left lines until tested, so this round is English only.

## 2. Translating a selection: Google Cloud Translation from the browser

**Endpoint:** Cloud Translation Basic (v2), `POST https://translation.googleapis.com/language/translate/v2` with a JSON body `{ q, target, format: "text" }`. The source language is detected when left out, and the reply includes `detectedSourceLanguage`. API keys work for every v2 method; v3 (Advanced) needs OAuth, so v2 it is.

**It works straight from a web page.** Tested from this app's dev server with a made-up key: Google answered with a readable `400 API key not valid`. A page can read Google's replies, so no proxy is needed. The key works in the `X-Goog-Api-Key` header, so it never sits in a URL, where it could end up in logs or history.

**Cost:**
- the first 500,000 characters a month are free (a $10 monthly credit)
- then $20 per million characters

**Getting a key** takes more than an AI Studio key. You need a Google Cloud project with the Translation API enabled and a billing account, even to stay within the free tier. The Settings text should say that briefly, and suggest restricting the key to jot.software and to the Translation API in the Cloud console.

**The app needs:**
- `https://translation.googleapis.com` added to `connect-src` in `public/_headers`
- the key stored like the AI keys: in this browser only, sent only to that host

**Target language:** Jot only knows English and Farsi, so it translates whichever way the selection isn't: Farsi into English, anything else into Farsi.
