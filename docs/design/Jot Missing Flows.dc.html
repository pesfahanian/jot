Hover lifts one step, pressed drops one. Hover is always less than selected — the same row-hover rule from the light theme — so a hovered row never reads as the open file.
The ring is --ring: 2px accent, keyboard focus only. Free-standing controls get it outside with 2px offset; flush controls (tabs, rows, menu items) get it inset, because an outside ring would be clipped by their neighbours. The offset gap is what keeps it visible around the accent-filled primary button.
Inputs don't get a second ring. Their focus is the accent border already used by search; stacking a ring on top would put accent on one element twice.
Caught: keyboard focus and the review view's "open flag" ring are the same token. That's fine only because review keyboard navigation is deferred (spec §6). If it ever ships, one of the two has to change.

Text holds, with one adjustment. At the 13px split size each pane gets about 41 columns once the gutter shrinks from 40 to 34 and the text inset from 16 to 12. That's enough for prose with soft-wrap — continuation lines take no line number. Font size stays at 13; going smaller to buy columns would be the wrong trade.
Code doesn't wrap, it clips. Wrapping a shell command breaks copy-paste and hides where the line ends, so fenced lines run past the pane edge with a › marker and scroll horizontally on their own.
Caught: each tab strip fits one tab. At 379px there's room for one full filename and nothing else, so tab overflow is no longer a hypothetical gap — it's the next thing to design. Unfocused panes mark their active tab gray; only the focused pane's is amber.
Caught: the controls don't fit. They sit on the focused pane only, and at this width render and export fold into a ⋯ menu; split stays as its icon and review shortens to one word.
