A sun/moon icon can't say whether it shows the current theme or the one you'd get by clicking — exactly the ambiguity the icon rule exists to catch, so this is text. It reads as one more status-bar cell because that is what it is: global state, label plus value, same shape as bytes 2 471. Click cycles light → dark → system; system appends what the OS currently resolves to, so the cell never lies about what you are looking at. Default is system.

inset 0 1px 0 #FFFFFF, 0 0 0 1px oklch(.90 .005 250), inset 0 -3px 0 oklch(.855 .006 250)
It holds, with one condition: the panel must sit on panel, not surface. A near-white key has no room above itself for a highlight, so the effect dies on the editor's own ground. On panel there is .075 of lightness left to white — close to the .09 dark has above its elevated surface — and the bottom inset does the rest. Verdict: keep it, and pin the panel ground as part of the token. The small keys read better than the large panel; at 12px radius the bevel is subtle enough to be easy to miss.
